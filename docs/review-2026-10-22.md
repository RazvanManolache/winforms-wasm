# Implementation review and next work — 22 October 2026

There is useful progress in the compatibility layer, especially Paint.NET's CPU drawing and history path. A real brush stroke, undo and redo were observed again in the browser. This is still a partial compatibility experiment: the normal UI is CPU-rendered, the new integration seams are optional, and platform-service persistence is not connected to ordinary applications.

This review combines inspection of the exported sources, fresh source-only builds/tests, and selected live browser workflows. It is not a full 62-app survey, a native/browser parity study, or a performance/GPU acceptance run. External-app captures came from the separately configured development host, not a source-only checkout containing those applications.

## What changed since the previous source update

- Paint.NET Direct2D controls now bypass the GDI self-paint path that hid their CPU-rendered output. The color wheel is visibly present. This is Direct2D compatibility implemented on the CPU, not Direct2D running in the browser.
- A browser text-raster bridge handles supported DirectWrite-layout text, retaining the embedded fallback when rasterization is unavailable.
- Additional CPU effect plumbing supports Levels token lookup, color-space conversion, tile rendering and the effect-dialog resume path. These pieces have native tests; this review did not establish a complete non-default Levels adjustment through browser input.
- History changes retain in-memory mementos and address unsupported waits/event-handle paths. A fresh brush stroke disappeared with Ctrl+Z and reappeared with Ctrl+Y. History persistence, bounded memory and long-session reliability remain open.
- `WfWasm.AppIntegration` and its 20 contract tests are included in the public source tree. `ControlLayerBridge` and `PlatformSessionBridge` define integration boundaries; neither is connected to production application execution.
- Source-only rewriter tests now declare their Drawing runtime dependency and search their test output when resolving metadata. Assertions were preserved. The runtime lookup helpers remain portable and the existing patched hosting package versions were retained.

## Fresh browser observations

See [capture provenance](screenshots/README.md) for images and viewport sizes.

- **Paint.NET:** one diagonal brush drag modifies the document. Ctrl+Z removes the stroke; Ctrl+Y restores it. In the document-only rectangle `(790,350)–(1030,520)`, the saved JPEGs contain respectively **632, 0 and 632** pixels with every RGB channel below 90. This independent image check supports this particular visible roundtrip, not arbitrary undo correctness. The title stays modified after undo; saved-state semantics were not verified.
- **Paint.NET limits:** History/Layers contain blank text or solid blue blocks; color-value controls have block/mosaic artifacts; the tool window is partly clipped. The actual Adjustments → Levels dialog opens, but the capture has incomplete controls and no visible OK/Cancel actions. Non-default parameter application/cancellation remains unverified.
- **MedicalApp:** Register new patient reveals the actual registration fields over the dashboard. Attempts to enter text did not produce visible text in the first-name field. Separate focus/key delivery, model mutation and repaint before assigning a root cause. No patient record was saved and no persistence claim is made. The demo clock hands changed between observations; the date/calendar and empty data areas still need investigation.
- **Map Selection:** clicking Brazil colors the actual country polygon cyan. The `SelectedCountries` area remains visibly empty, so selection painting is verified while selected-item/data-list behavior is not.
- **Source-only build:** only the built-in form is available and its button increments the visible counter. The external application library remains optional and excluded.

## Ordered work for the next agent

Finish the current coherent task and its checks first. Then use the following order. Preserve the successful stroke/undo/redo and map workflows; do not weaken failure gates or count callback completion as an observable result.

### 1. Make real input and visible UI behavior dependable

Reproduce the MedicalApp first-name input problem, the missing Map Selection list, and Paint.NET's missing panel/dialog text. Trace hit target → focused control → key/text event → model value → invalidation → visible pixels. Read back the actual model/value in addition to capturing output; distinguish an input-delivery issue from invisible painting. Test ordinary keys, modifier chords, text replacement, selection, tab focus and cancel. Add a deliberate dropped-input/suppressed-repaint mutation to prove the oracle detects each failure.

For Paint.NET, test supported adjustment input, OK, Cancel and window-close separately. Verify independent document pixels and history identity/count, then undo/redo. Opening a dialog and running an identity token is insufficient. Restore usable layout and all necessary actions at ordinary viewport sizes before claiming adjustment workflows work.

### 2. Fix the new text-raster transform boundary

`CpuPaint.BlitRaster` transforms the origin but increments destination pixels with `dx0 + sx` / `dy0 + sy`. It does not apply axis scaling to the raster body, despite the nearby comment describing axis-scale support. The tint test covers identity coordinates, not that behavior. Implement the supported affine mapping or explicitly reject unsupported transforms. Add independently calculated cases for 2× and fractional scale, negative scale, translation, clipping and non-default DPI; verify origin and extent. Rotation/shear must have a declared supported/rejected policy.

`TextLayoutRaster.TryRasterLayout` uses reflection and returns null on unreadable/unrasterizable input. Preserve fallback behavior while making unexpected failures diagnosable when diagnostics are enabled. Do not equate a returned raster with text-layout parity.

### 3. Complete one real GPU-control pilot

`WinFormsAppHost` still rejects `WfWasm.RequireGpuRendering` before painting. The host's GLES project reference is explicitly for the probe. The added AppIntegration bridge has no production consumer. Existing CPU bitmap retention is useful but does not establish accelerated drawing.

Follow [the integration map](integration-bridges.md) and [integration handoff](integration-agent-prompt.md). Wire one existing real control through ordinary host invalidation/input, command recording, resource ownership, retained composition and presentation. Prove correct independent pixels, no app repaint on placement-only updates, resource reuse, resize/context-loss recovery and cleanup. Count whole-control raster uploads and readbacks. Keep the strict required-GPU policy intact until the requested capabilities are actually available.

### 4. Connect platform services and settle synchronous dialog semantics

The main host/server do not reference the AppIntegration project or install the platform broker. `WasmRegistry` still returns missing/default values and makes writes no-ops. The separate SQLite/file/print modules and their tests do not change that fact.

Connect one app/session-scoped transport and one real setting roundtrip first. Prove persisted typed values after restart, write-failure reporting and separation between apps/users/sessions. Then prototype one synchronous `ShowDialog()==OK` caller across the asynchronous browser picker boundary. Do not return early and claim the following file read is correct. Establish locals/exception/finally/cancel semantics before expanding continuation rewrites or moving execution to a worker.

Add an open/edit/save workflow with independently decoded file bytes, cancelled/denied access and late-session replies. Bind file access to declared mounts or explicit user grants. Connect print-page generation and browser preview separately; browser preview/afterprint cannot prove physical printer delivery.

### 5. Measure latency and long-session resource behavior

Collect comparable repeated cold/warm load samples and input-to-independent-visible-response samples, with normal diagnostics disabled. Report payload, actual network transfer, HTTP cache, transformed-assembly cache and session memory reuse separately. Near-zero transferred bytes in a warm session can coexist with substantial app payload and startup time.

Before redesigning loading/scheduling, measure the synchronous dependency resolver, transform/cache work, managed event handling, paint, serialization, upload and presentation. Use the same app/build/viewport/cache policy and report p50/p95/max plus missing responses. Screenshot automation duration is not physical input-to-photon latency.

The new history strategy strongly retains data because disk persistence is stubbed. Verify memory plateau over many edits, history trimming/clear, document close and session replacement, including forced GC. Verify worker/event neutralization does not silently change ordering, cancellation or cleanup. Maintain explicit bounds on surfaces, histories, outstanding requests and selected files.

### 6. Make acceptance reproducible from the public tree

Keep source-only and external-fixture gates explicit. Supply fixture paths through configuration; report missing requirements without silently treating them as passes. The gallery README's earlier claim that Paint.NET Ctrl+Z does nothing is now historical: this review observed a working roundtrip. Update the automated gallery case and run it against a pinned generation before declaring the runner fixed.

Replace the gallery runner's fixed `CANVAS_OFFSET` with observed canvas/frame geometry and correct coordinate transforms. Add independent selected-list, form-field and document/history oracles. Catch and report failed or shape-mismatched rewriter rules: the current best-effort catch paths can leave a rule unapplied without an actionable rule result. Validate required transformations, emitted IL stack/signatures and actual browser behavior together.

## Scope of this publication

Included: project-owned base source, adaptation rules, tests, integration documentation, licenses and unaltered browser screenshots. Excluded: external app executables/DLLs, converted assemblies, vendor demo trees, loose app assets, caches, logs and private runtime data. Screenshots show partial compatibility and retain application-owner attribution. No full GPU, performance, platform parity or multi-user hosting claim is made.
